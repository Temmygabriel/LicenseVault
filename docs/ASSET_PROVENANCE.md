## The protected resource

**Name:** Commercial Brand Asset Pack
**Nature:** fictional demonstration resource
**Real-world rights:** none. It is not a real brand, product, or client's material, and it is
never described as being under a real legal licence.

### What the bytes actually are

The plaintext is **not** a bundle of brand files. It is a single JSON delivery manifest, authored
in this repository by `buildProtectedContent()` in `tools/spike/build-vault.ts` (lines 213–230) and
encoded there as UTF-8. It is deterministic: the same run id and the same two on-chain identifiers
produce the same bytes.

That distinction is written down on purpose. The manifest *describes* a five-file brand pack, and a
reader could otherwise assume those five files — about 1.6 MB of EPS and PDF — are what sits behind
the gate. They are not. The manifest is the payload; the file list is metadata inside it. What the
gate actually protects is the **key**, not any particular secret bytes, and the run's own artifact
says so in as many words (see the note quoted below).

### The payload

| Field | Value |
|---|---|
| Plaintext bytes | 804 |
| Ciphertext bytes | 832 |
| **Plaintext SHA-256** | `46cab4a8232e4eea226500b424416a353618c8606008d374dbb15f56bc864cd7` |
| Cipher | AES-256-GCM |
| Layout | `12-byte IV ‖ ciphertext ‖ 16-byte tag` |
| Released field in payload | `2026-10-05` |
| Licence the payload names | Commercial Use |

The digest is the check the unlock is judged against. It was computed **before** any unlock was
claimed and compared again **after** the decryption, and the two agreed byte for byte —
`decrypted-resource.json` records both values and `"matches": true`. That is the difference between
saying *"it decrypted"* and showing that what came back is what went in.

### Contents declared inside the payload

| File | Bytes | Declared media type |
|---|---:|---|
| `brand-mark-primary.svg` | 18,442 | `image/svg+xml` |
| `brand-mark-inverse.svg` | 17,908 | `image/svg+xml` |
| `wordmark-horizontal.eps` | 402,115 | `application/postscript` |
| `palette.coco` | 3,120 | `application/octet-stream` |
| `usage-guidelines.pdf` | 1,204,880 | `application/pdf` |

These are **declared metadata**, not files that exist in this repository and not files that were
encrypted. Nothing in the demo reads them. They are present because a delivery manifest that listed
nothing would be a prop with no shape — and the payload is a document whose contents have to look
like something for the gating to mean anything.

### The payload's own note, quoted

`evidence/licensevault-aeneid-001/protected-content-manifest.json` carries this, and it is the
clearest statement of what the run proves:

> The plaintext of this asset is published here too — it is a public brand pack. The point of the
> run is that the KEY is gated, not that these particular bytes are secret. The hash below is what
> the unlock is checked against.

`protected-content.bin` (the sealed blob, 832 bytes) is committed alongside it, so a judge can
re-derive the digest from the sealed bytes and the recovered key rather than taking our word.

## Interface artwork

Every image in the interface is **our own inline SVG, drawn in this repository**. Nothing is
photographed, traced from a screenshot, downloaded, or generated by an image model. This matters
because the UI preflight pack uses paper photographs as *art direction* — they set the tone, they
are not assets to paste over the app.

| Asset | Where it lives | Origin | Notes |
|---|---|---|---|
| `VaultMark` — shield and keyhole | `components/ProtectedAsset.tsx` (inline) | Drawn here | `viewBox 0 0 40 46`, stroke uses `currentColor`; the keyhole is the one warm mark, `#A7613C`. Decorative: `aria-hidden`, `focusable="false"`. |
| `SealedRecordArt` — three offset pages with a stamped keyhole | `components/ProtectedAsset.tsx` (inline) | Drawn here | `viewBox 0 0 150 122`. Abstract ruled lines, **no text**, so it cannot imply a document that does not exist. Decorative and hidden from assistive technology; the heading beside it is the real content. |
| Favicon / app icon | `app/icon.svg` | Drawn here | 64×64, shield + keyhole on `#F4F1E8`. Same mark as `VaultMark`, redrawn at icon scale using literal hex rather than `currentColor`, because a favicon has no inherited colour. |

Palette values in the artwork (`#1C1D1B` ink, `#A7613C` copper, `#F4F1E8` canvas, `#F9F7F1`,
`#EFE5D5`, `#A99A82`, `#D0C6B6`) are the project's own tokens or tints derived from them. None is
sampled from a third party.

## Provenance rules

1. **No third-party copyrighted material.** Nothing is taken from a real brand, a stock library, or
   the open web, unless its licence explicitly permits use and the licence is recorded here. Nothing
   in this project currently requires that exception.
2. **Generated content is labelled.** If any image is produced with a generative tool, that is
   recorded, along with the tool and date. **No image in this project was produced that way** — the
   three marks above are hand-authored SVG.
3. **No embedded text in images.** Per the visual direction, imagery carries no text — which also
   avoids accidental trademark use.
4. **Every asset records a digest.** So a judge can confirm the recovered plaintext is exactly the
   asset that was protected.
5. **Nothing is presented as a real licence.** The asset is a prop for demonstrating a mechanism.
   It is never described as being under a real legal licence.
