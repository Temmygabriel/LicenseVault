## PHASE 5 — Preserve correct state and error handling

Use the existing state machine. Extend it only where necessary, with typed events and evidence.

Maintain these distinctions:

- NO LICENSE: the real licensing condition refused the read.
- VERIFICATION ERROR: the system could not establish a reliable answer.
- LICENSE VERIFIED: the real licensing check succeeded, but the content has not necessarily been decrypted.
- ACCESSING: the real protected read/decryption is in progress.
- ACCESS GRANTED / UNLOCKED: the actual protected content has been recovered and validated.

A successful license check alone must never trigger ACCESS GRANTED.

Also distinguish wallet cancellation, wrong network, insufficient balance, failed transaction, malformed request, partial-collection timeout and decryption failure. Never turn these into a license denial.

The ephemeral decryption key must not be persisted in local storage, server logs, evidence files or repository artifacts. Display the real recovered content only after decryption has succeeded.
